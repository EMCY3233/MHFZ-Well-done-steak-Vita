# INI-DATA virtual serializer candidate resolved

Static source identity remains user ELF SHA256 2e7d656b0862dff256c8224c6f1d52952a9d631562a9ce65e337b86994a8fb9d. Existing Ghidra 12.1.4/VitaLoaderRedux laboratory analysis and original PT_LOAD-mapped words were inspected. No client or commercial function was executed.

The prior setter path constructs a candidate object with 116 bytes through 0x821208e8. Its recorded 504-byte body assigns virtual-table address 0x82b287a8 to the object. Mapping this table through the ELF program headers gives cell 0x82b287c8 at slot 0x20, containing Thumb pointer 0x82123583; its aligned function entry is 0x82123582. The latter is the candidate target for the save worker's observed slot-0x20 call when this constructed object remains the receiver. This is a conditional static chain, not proof of runtime object identity in every save.

The function at 0x82123582 has a recorded 630-byte body. Its decompilation describes three arguments: receiver, destination buffer and capacity. It iterates receiver-owned grouped collections, appends strings and separators to a temporary string, appends newline bytes for selected entries and uses fallback text for an empty result. It then copies a bounded prefix to the supplied destination, adds a zero terminator and releases temporary heap storage. The original epilogue sets r0 to 1; it does not return the copied length. The earlier void decompiler signature must not be used as an ABI conclusion. The precise text grammar, encoding, validation and type layouts remain unproven; this report does not publish those strings or pseudocode.

The final copy branch has now been checked against original instruction listings; INI-COPY-BOUNDARIES.md records its equality and zero-capacity limits. No safe general-purpose bounded-copy contract or reachable exploit is asserted. The known save-worker path supplies a positive 512000-byte capacity after clearing its allocation, but its metadata size remains 512000 in the bounded evidence. A shorter meaningful text prefix therefore does not by itself authorize shrinking the original save request. Trimming trailing zeroes would require proof from the corresponding reader.

The temporary string is an additional allocation not included in the fixed buffer subtotal in INI-MEMORY-BUDGET.md. Its growth depends on receiver contents. Thus the 2.52 MB hypothetical INI-only subtotal remains partial; no Vita memory availability or maximum process usage has been measured.

ini-vtable-metadata.json publishes only original-base table addresses, targets, file offset and source hash. Private constructor and serializer evidence stays in ini-constructor-private.json and ini-slot20-private.json. No binary bytes, commercial resources, saves, credentials or pseudocode are published. Original inputs, firmware/plugins and console installations remain untouched.

Next focused steps: verify the final copy branch in original instructions, identify the corresponding text reader and its size/terminator behavior, and resolve the actual worker call arguments/lifetime before choosing a per-logical large-record policy. The native payload limit remains 163840; full 512000-byte INI-DATA is still unsupported. Physical isolation and persistence also remain unproven.
