# INI-DATA receiver setter located

The static follow-up through the independently published owner pointer 0x839fd870 identifies a concrete field-zero setter, rather than extending the previous getter scan. The source ELF remains SHA256 2e7d656b0862dff256c8224c6f1d52952a9d631562a9ce65e337b86994a8fb9d. Ghidra 12.1.4/VitaLoaderRedux was used directly on the existing laboratory database; no client execution or binary modification occurred.

OwnerAliasPcode.java examines SSA aliases of the owner global. All 25 containing functions supplied by current references decompile. The final run reports 1610 distinct SSA varnode roots, 703 use rows, 646 PHI boundaries, 57 direct call uses and no direct exact-zero store within its local propagation. These are decompiler-node counts, not 1610 machine loads. Following a reported call, rather than interpreting the zero direct stores as absence, exposed the setter.

At 0x823cc86e the caller invokes 0x8211c0cc with the owner container as its first argument and the candidate object as its second. The original instruction context confirms the owner global is loaded immediately before the call and the candidate register is passed separately. The setter preserves the two arguments, checks the previous field-zero object, calls cleanup/free when needed, and stores the replacement into field zero at 0x8211c0de. Its recorded body is 24 bytes. This resolves where a nonzero receiver can be assigned; the earlier negative getter-only scan could not establish that.

The caller 0x823cc79c has a recorded 226-byte body. Under its initialization condition, it first obtains the container through getter 0x8211b918 and tests field zero. If empty, it requests 0x74 (116) bytes and passes a successful allocation to constructor 0x821208e8 with two fixed data addresses, then calls the setter through the owner global. The decompilation also shows a later field-zero virtual call in that state path. These observations establish a candidate construction/assignment path, not proof that it runs in every save session or that allocation/initialization succeeds.

The next concrete task is constructor 0x821208e8: identify its virtual table and resolve offset 0x20, then verify the serializer's arguments, output length and ownership against the save worker. Do not confuse offset-zero virtual calls in this caller with the separate offset-0x20 save operation. Runtime branch conditions, object types and format remain unproven. Capacity is unchanged at 163840 payload bytes.

The first owner script incorrectly looked only for explicit LOAD operations and reported zero roots. It was corrected to include memory-valued SSA inputs, then duplicate varnodes were filtered. Only the final counts above are evidence. PHI propagation and indirect effects remain outside coverage. Owner-pointer references and all pseudocode/instruction listings remain local; the public evidence file contains addresses, counts and an evidence hash only. No commercial bytes, resources, saves or credentials are published. No console or original installation changed.
