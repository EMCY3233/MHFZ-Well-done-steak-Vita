# INI read-holder producer and completion quantities

Source remains unchanged user ELF SHA256 2e7d656b0862dff256c8224c6f1d52952a9d631562a9ce65e337b86994a8fb9d. Existing Ghidra 12.1.4/VitaLoaderRedux metadata and original instruction listings were inspected; no commercial function ran.

The loader starts holder worker Thumb 0x82140479, aligned 0x82140478 (800 recorded bytes), through its existing thread helper. The holder initially clears source/capacity/expected-size fields. The worker queries a file-size wrapper 0x8212d45e, which calls import sceFiosFHGetSize. Original instructions store that pre-read result in holder +0x12c at 0x82140578. Therefore this field is an expected size established before read completion, not a measurement of completed input bytes.

For a preallocated read buffer, original instructions at 0x82140564..0x82140576 compare expected size with existing capacity and select error value 5 if insufficient. When storage must be allocated, the path rounds expected size upward to a 2048-byte multiple at 0x82140588..0x8214059a and uses the array allocator at 0x8214059e; the result becomes holder source +0x124 at 0x821405a2. The arithmetic is 32-bit and no whole-domain overflow guarantee is asserted. For the observed 512000-byte entry the rounded value is also 512000, so page rounding alone adds no terminator space.

The read dispatch 0x8214063a calls helper 0x8212d4ae with the source pointer and allocation capacity. A separate completion context/result is used. The read polling helper 0x8212ee00 tests the context's completion flag and copies its result word to the holder's +0x134 output. Once completion is reported and the event wait finishes, the worker stores state 1 at 0x82140752. State publication and expected-size publication are distinct operations.

The helper launches thread Thumb 0x8212d6f3, aligned entry 0x8212d6f2 (376 recorded bytes). Its recovered flow selects sceFiosFHReadSync for reads, retries negative results and eventually publishes a result word plus completion state. No equality between that result and the requested allocation capacity was identified in this bounded completion path. The previously inspected loader copies expected size +0x12c and does not establish a comparison with the separate +0x134 result in its local preparation segment. This is not proof that every producer/API layer allows short reads or that a runtime failure is reachable. Full FIOS ABI/result semantics and all upstream invariants remain pending.

The local primary NID database identifies sceFiosFHGetSize as 0xC5C26581 and sceFiosFHReadSync as 0x76945919. Its public headers in the inspected trees do not provide these function prototypes. Decompiled extra arguments and 64-bit return handling must therefore not be treated as a verified FIOS ABI. The report deliberately distinguishes expected-size, capacity, API result and completion flag instead of naming them interchangeably as bytes read.

Integration consequence: completion state alone must not authorize a blind expected-size copy. A new bridge needs independently justified available-byte, capacity, termination, ownership and completion checks, while preserving original status behavior where required. No bridge is implemented and capacity is unchanged. The next concrete check is the read-thread's original result/flag publication and any producer guarantee of the result semantics; no additional adjacent-vtable scan is needed.
