# Private eight-slot store adapter

private_store.c/h provide callback functions for the native coordinator through sceIoOpen/Read/Write/Close. Only eight fixed paths under ux0:data/MHFZL0001/wdsv004/ are accepted: manifest-a/b, ini-a/b, pri-a/b and character-a/b. These are a new experimental namespace; existing WDSV003 journals and original game paths are not used or migrated.

No directories are created. The caller-owned pool requires parent_verified==1, which must only follow independent directory identity, mount and ownership checks. Setting this flag is not evidence that those checks happened; none has been established in the client. The ENOENT mapping 0x80010002 is inherited from WDSV003 emulator-source evidence and remains unmeasured physically. Parent verification is required because the same error may indicate a missing directory. Existing empty files are present zero-length buffers, not absence or initialization permission.

The persistent pool occupies 983636 bytes: six record buffers of 163876 bytes, two 188-byte manifests and a four-byte precondition flag. It must not be allocated on the thread stack. Observation buffers last until the next read. Source buffers overlapping any part of this pool are rejected on writes so replacement data cannot be overwritten during subsequent observations. The caller must also ensure output descriptors and pool/input objects do not overlap. The adapter holds no lock and cannot enforce ownership against another process.

Read loops handle partial reads and probe one extra byte at capacity. Negative/overreported reads, non-EOF extra data and close errors fail. Write loops reject zero progress, negative/overreported lengths, close errors, incorrect logical IDs/slots, non-188-byte manifests and records outside 36..163876 bytes. Record semantic validation remains the coordinator/planner responsibility. No flush or power-loss guarantee is claimed.

31 ARM cases pass with only OS functions mocked: all missing, empty existing manifest, eight fixed slots, partial I/O, exact EOF capacity, oversize files, size/identity rejection, pool alias rejection, access errors, read/write errors, zero progress, overreports and close failures. Outputs remain unchanged on read errors, but pool contents may have changed; the epoch must block. The first compile found misleading indentation under -Werror; it was corrected before the passing test run.

The adapter plus coordinator/planner/readers/native SHA also link against local VitaSDK SceLibKernel and SceIofilemgr stubs with no undefined symbols. This establishes build compatibility only; no generated ELF is published or executed on Vita. Callback-level coordinator tests and OS-level adapter tests are separate; a combined pipeline fault harness remains next. No original files, client, firmware, plugins or console were modified. INI-DATA still exceeds the current write capacity, and real isolation remains unproven.
