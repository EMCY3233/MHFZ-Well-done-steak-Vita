# Native batch publication coordinator

batch_commit.c/h implement the publication protocol through injected storage callbacks. The planner, record and manifest validation, snapshot selection, CRC and SHA computations execute as compiled ARM code. Only read/write callbacks are mocked by the harness. This is not a filesystem adapter or a client hook.

An exclusively owned epoch starts at zero. The coordinator blocks it immediately, reads baseline buffers, saves manifest bytes independently of callback buffers, prepares the candidate, writes changed records, reads them back, requires unchanged baseline manifests, validates the full candidate, publishes the manifest, and finally recovers the complete visible snapshot. Only confirmed success clears the block. All failure paths preserve the output snapshot. A blocked epoch performs no callbacks on subsequent attempts. Reinitialization requires independent recovery and ownership checks.

Ten ARM cases pass: success; failures of each of the three reads; record acknowledgment/readback; changed baseline; corrupt unchanged member; manifest acknowledgment/readback. The harness reuses its observation memory, exercising the saved baseline copies. It checks publication ordering, output preservation, blocked retries and the recoverable new generation after an unacknowledged full manifest write. A first harness run missed the Python recovery-oracle import; that harness error was corrected before producing the passing report. batch-commit-arm-results.json records cases and the original test ELF hash. No ELF is published.

Callbacks return zero only on acknowledged completion. Buffer arrays must be fully populated on successful reads; their bytes remain immutable and valid until the next read. Replacement bytes remain immutable for the whole operation. Output and state must be valid and disjoint from inputs. The returned snapshot borrows the last observation buffers. Exclusivity is an external precondition, not an implemented lock. Callback error blocks the epoch even if data has already changed; this is not rollback.

For publication the coordinator currently accepts only absent or exactly 188-byte manifest slots. This is deliberately narrower than read-only recovery, which can fall back around truncated candidates. A truncated manifest therefore requires independent recovery/reconciliation before publication; it is not automatically overwritten here.

Readback confirms visible bytes, not durable media persistence. No power-loss guarantee, Vita I/O adapter, physical storage test, larger INI-DATA capacity, client identity/mount isolation or launch capability is established. Next work is a bounded private store adapter with explicit observation lifetimes and independently justified recovery handling. No client or console was executed.
